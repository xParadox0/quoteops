## Implementation and schema (complete)

- DEFECT (high) \u2014 an anonymous client can exhaust the 512 MiB web-container limit with concurrent scrypt work. `passwords.py:7-8,61-63` documents/uses 32 MiB per `n=2**15,r=8,p=1` computation (with a 64 MiB OpenSSL allowance). Login admits 30 attempts per network per 15-minute window (`config.py:105-108`, `auth.py:389-403`) before blocking, and there is no application concurrency bound. Thirty concurrent unknown-address requests can therefore demand about 960 MiB of scrypt working memory. The persistent counter limits attempts over time, not computations already admitted concurrently. With a spoofable configured client-IP header or multiple source networks the bound is still weaker.
- DEFECT (high) \u2014 a verification-mail write failure strands the newly created account. `auth.py:335-342` commits company and owner creation before `_send`; on `OSError` it returns 503. A retry finds the existing account (`:330,339-340`) and sends the \u201calready exists\u201d mail, which contains login/forgot links but no verification link (`:220-227`). There is explicitly no verification resend route. Reproduction: make `QO_MAIL_DIR` unwritable, submit a valid new signup, restore it, submit the same signup; the account remains unverified and the second mail cannot verify it. This conflicts with F4 and the displayed \u201ctry again\u201d recovery instruction.
- DEFECT (medium) \u2014 account existence is distinguishable by timing at signup and forgot despite uniform HTTP responses. Signup hashes on both paths, but only a new address opens another connection, takes the advisory lock, counts companies, and inserts company plus owner (`auth.py:267-282,330-340`). Forgot only for an existing enabled account constructs a token and writes/fsyncs a mail file (`:461-470`, `mail.py:16-21`). Repeated measurements can separate these paths. The HLD promises signup timing does not reveal existence, and the review brief explicitly includes timing enumeration.
- OBSERVATION \u2014 verification tokens are stateless and bound only to canonicalized email plus expiry, not an account id/state (`tokens.py:28-32`, `auth.py:348-363`). Reuse for the same account is idempotent as promised. If future account deletion/re-creation permits the same address inside 48 hours, the old link would verify the replacement account; Stage 2a itself has no such deletion path.
- OBSERVATION \u2014 throttle arithmetic is internally consistent. First hit stores 1 and is allowed when limit >=1; hits through `p_limit` are allowed; hit `p_limit+1` sets the block and is denied. During a block hits increase but its end is preserved. At `blocked_until <= now()` or an unblocked window boundary (`window_start <= now()-window`) the row resets to hit 1. Thus limit 1 allows one and blocks the second; limit 0 blocks the first (configuration rejects zero). The atomic upsert serializes a key\u2019s races, and an attacker cannot extend or clear an active block. Expired unblocked rows are pruned opportunistically after one day.
- OBSERVATION \u2014 throttle storage can grow with attacker-selected email addresses and client addresses. `kind` is server-selected and the stored key is a secret-salted SHA-256, but each distinct value creates a row retained for up to a day; there is no table-wide cardinality cap. Normal per-network short-circuiting limits this per source, while a trusted-but-client-spoofable header or distributed sources bypass that practical bound. The cleanup also scans/deletes old rows on every hit.
- OBSERVATION \u2014 CSRF checks cover every POST: signup/login/forgot/reset use Origin plus HMAC double-submit (`auth.py:147-153`), and logout uses Origin plus a session-bound HMAC (`:424-441`). Exact normalized origin comparison rejects `null`, wrong scheme/port/subdomain, userinfo tricks, and uses the parsed Referer origin only when Origin is absent; absent/malformed Referer is rejected. Session tokens are 32 random bytes, only SHA-256 is stored, sign-in rotates them, cookies are HttpOnly/SameSite=Lax/Path=/ and Secure by default, logout deletes the row/cookie, expiry is absolute seven days, reset deletes all sessions, and the SQL lookup rejects expired/disabled/suspended/deleting accounts.
- OBSERVATION \u2014 token checks use HMAC-SHA256 with kind, email, integer expiry and reset hash fingerprint; constant-time comparison; a 1024-character input cap; strict base64 decoding; and `expiry <= now` rejection. Signup canonicalizes by strip/lower before signing, excludes `|`, whitespace and controls, and length-checks the address. Cross-kind use, signature truncation, tampering, expiry-boundary use, and reset replay after a hash change fail. Base64 spellings need not be textually canonical, but decoded payload/signature identity gives no replay bypass because tokens are stateless.
- OBSERVATION \u2014 the signup cap is rechecked under a transaction-scoped advisory lock, and company/owner inserts share one transaction; a unique violation rolls both back. Inputs are bounded before hashing/insertion, mail headers reject CR/LF, template autoescape is enabled, no `|safe` or string-built HTML/open redirect/request-derived link exists, and mail links use validated `QO_BASE_URL`. Logs contain exception class names only; uvicorn access-log configuration is checked separately below. Database failures become the generic guarded 500 page on auth routes; `/healthz` returns its explicit 503.
- OBSERVATION \u2014 when `QO_CLIENT_IP_HEADER` is set, the application unconditionally trusts the first comma-separated value (`auth.py:110-116`). A client can spoof it unless the only reachable reverse proxy strips/overwrites that header. With the default unset, a single reverse proxy makes every user share its socket address and therefore the same per-network limits.
- OBSERVATION \u2014 the HLD\u2019s Fetch claim is incorrect: `Referrer-Policy` controls the `Referer` header, not the POST `Origin` header. `no-referrer` does not by itself turn a same-origin form POST\u2019s Origin into `null`; opaque origins and certain privacy-sensitive redirects can produce `null`. `same-origin` remains an accepted design choice here.

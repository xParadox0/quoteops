## Pass 1 (reviewed head c793188): fail

- Verifier pass 1: fail, one DEFECT (medium). The admin sign-in accepts an unbounded form: passwords._matches normalises the whole submitted string (NFKC) before it decides the length is too long, and nothing caps the request body, so a few large concurrent requests can allocate a lot of memory inside a 512 MiB container. The verifier ran no PostgreSQL or Docker. The orchestrator found that the public app has the same gap (login, verify, reset, invite accept), older than this stage: the stage 2a attack that sent 5 MB passwords measured only speed. Everything else was accepted: TOTP matches the RFC 4226 and 6238 vectors, the six functions and two tables, the generic sign-in answer and its work parity, the CLI, the guard refactor, compose separation, and 18 of 18 hand mutations map to a failing test. Observations kept: qo_session_lookup still returns a sysadmin session row to qo_web (the application ignores company-less rows; a filter would be defense in depth); the per-email lockout; a shared proxy address shares one IP bucket; distinct QO_SECRET and QO_ADMIN_SECRET are documented but not enforced. - Verifier pass 2: pass. The pass-1 defect is fixed in shared code for both apps (request body limit of 16384 bytes before any route runs; a password over 1024 raw characters is refused without being normalised and still costs one scrypt). No new defect. The file docs/evidence/stage2b2-verdict.md is the verifier's own text, byte for byte, sha256 46b105ce3942a01e8b35f2b89fc63f4a8f9bba77cbb678eca9ef690ed9fdc5b1.
- Orchestrator replay of 40c9d42: 1022 tests passed; the 171 new tests fail 163 against the previous code. A live run with the real admin service and the real public app under uvicorn against PostgreSQL: with 40 and 120 concurrent passwords of 1,000,000 characters the old code peaked at 200 and 249 MB (idle 68 MB, about 1.5 MB per request in flight) and the new code stayed at 68 to 70 MB with 413 answers; a 5 MB chunked body gives 413; a declared 1 GB length with no body, which hung the old code until a 10 second timeout, gives 413 at once; Content-Length abc and -1 give 400.
